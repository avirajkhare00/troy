Case study

We taught a model bhai-lang. On a MacBook. In 40 minutes.

Bhai-lang is a toy programming language with Hindi-slang keywords — programs start with hi bhai, print with bol bhai, and end with bye bhai. No frontier model writes it reliably; it's too niche to matter to anyone with a GPU cluster. Which makes it a perfect test of the local fine-tuning thesis: one person, one M1 Pro with 16 GB, one troy.yaml.

The result first

Ask in English or Hinglish; get a runnable program. Scored by executing every generated program in a bhai-lang interpreter and comparing stdout to a reference — not by eyeballing strings.

The generalization failures are reported on purpose: a model card that only lists wins is marketing, not evidence.

The actual work was the data, not the training

There is no bhai-lang corpus to scrape. So the dataset is synthetic — and the rule that made it work: every training example was execution-verified before inclusion. A small Python interpreter for bhai-lang runs each generated program and checks its output against an independently computed answer. Bad programs never reach the model.

Three things that bit us (so they don't bite you)

  1. fuse with --dequantize

    Fusing a LoRA back into 4-bit weights loses the adapter deltas to quantization noise. The published model is the LoRA fused into the base and dequantized to fp16.

  2. no system message

    The model was trained on bare user turns. Adding a system prompt at inference degrades format adherence. Match your inference format to your training format, exactly.

  3. extract, don't trust

    Generation may not stop cleanly at end-of-turn. Pull the program with hi bhai[\s\S]*?bye bhai and discard the rest.
