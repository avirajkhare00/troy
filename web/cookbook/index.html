Cookbook

The tool is small. This is what it can do.

Troy stays a thin contract: a YAML file in, a trained model out. Everything you can build with that contract lives here instead — as recipes. Every recipe on this page was run end-to-end on a MacBook (M1 Pro, 16 GB) before it was written down; the outputs shown are real.

Before you start · three families verified on M1 Pro, 16 GB

Choosing a base model

The recipes below use Qwen3-0.6B because it trains in minutes on the 16 GB machine they were verified on — not because Troy is tied to it. base: accepts any model mlx-lm supports: Llama, Qwen, Mistral, Gemma, Phi, SmolLM, DeepSeek, and the rest of the mainstream open families. Point it at a pre-converted 4-bit repo from mlx-community for the fastest start, an original Hugging Face repo, or a local path.

troy doctor prints this guidance for the machine it runs on. Bigger bases follow recipes more faithfully — the same 20-example persona dataset that occasionally garbles on 0.6B speaks fluent pirate on Llama-3.2-1B. One format note: troy export -f gguf covers llama, mistral, and mixtral architectures; the default MLX export covers everything.

Recipe 01 · SFT · verified on M1 Pro, 16 GB

Give a model a voice: the persona bot

Teach a small model to answer every support question in a fixed persona — here, a pirate-voiced help desk. Twenty examples are enough to move the style; more examples make it stick harder. Same recipe works for brand voice, formality level, or a mascot.

Recipe 02 · SFT · verified on M1 Pro, 16 GB

A text-to-JSON extractor

Turn messy sentences into structured records. Use the completions format — a prompt in, exactly the JSON you want out. Fifty synthetic examples produced an extractor that generalizes to entities it never saw. The same shape works for invoices, log lines, or contact details.

Recipe 03 · DPO · verified on M1 Pro, 16 GB

Teach taste, not facts: preference tuning

Some things are easier to show than to describe: for each prompt, give a chosen answer and a rejected one, and DPO moves the model toward your taste. Here: concise answers over rambling ones. Ten pairs, thirty iterations. Troy's DPO recovers the reference model by zeroing the LoRA scales — no second copy of the weights in memory. (Also see recipe 06: ORPO uses the same data with no reference model at all.)

Recipe 04 · Serving · verified on M1 Pro, 16 GB

Your adapter behind an OpenAI-compatible API

Anything that speaks the OpenAI API — a script, an app, a framework — can use your fine-tuned model. troy serve picks up the adapter from your config automatically and serves it on localhost. Nothing leaves your machine.

Recipe 05 · Export · verified on M1 Pro, 16 GB

Train here, run anywhere: ship to Ollama

GGUF is the lingua franca of local inference — Ollama, llama.cpp, and LM Studio all speak it. Fine-tune a llama-architecture base (SmolLM2, Llama, Mistral), export once, and the result runs on machines that have never heard of MLX.

Recipe 06 · ORPO · verified on M1 Pro, 16 GB

Same preferences, no reference model: ORPO

ORPO learns from the same chosen/rejected pairs as DPO, but folds the preference signal into the SFT loss — so there is no reference model in the math at all. On this machine that made it 2.3× faster than DPO (3.2 vs 1.4 it/s) with the same outcome. When you have preference pairs, try ORPO first; reach for DPO when you specifically want to stay anchored to the base model's behavior.

Recipe 07 · Vision SFT · verified on M1 Pro, 16 GB

Beyond text: fine-tune a vision model on your images

Teach a vision-language model your visual domain — product photos, documents, UI screenshots. The contract stays one YAML file; the only change is that data.train points at a folder: images plus a metadata.jsonl of questions and answers. A 2B VLM trained in 2.4 GB peak memory here. Needs the vision extra: pip install 'troy-cli[vision]'.

Recipe 08 · Data synthesis · verified on M1 Pro, 16 GB

No dataset? Point Troy at your docs

The hardest part of fine-tuning isn't training — it's having a train.jsonl. troy data synth runs a teacher model locally (picked automatically for your Mac's memory — teachers only infer, so they can be bigger than what you train) and turns a file or folder of docs into grounded Q&A pairs. Nothing leaves the machine. Then train on it with any SFT recipe above.
