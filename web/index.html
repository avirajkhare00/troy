Apple Silicon · MLX · LoRA

Fine-tune on the Mac you already own.

Troy turns one YAML file into a LoRA training run on Apple Silicon. No CUDA, no cloud, no training pipeline — the model trains right there on your MacBook.

brew install troy See the workflow

Also on PyPI: pipx install troy-cli. Open source, Apache-2.0. Requires an M1 or later.

Five commands, start to shipped.

Each step is one command. The order is the whole method.

  1. troy doctor

    Checks your chip, unified memory, Metal, and MLX — and tells you what model sizes this Mac can train.

  2. troy init

    Writes a troy.yaml from a template — SFT, DPO, or ORPO — plus sample data to replace with yours.

  3. troy data synth

    No dataset? A local teacher model writes one from your docs or a task description — or troy mesh and every iPhone on your Wi-Fi generates it for you.

  4. troy train

    LoRA / QLoRA fine-tuning on Metal. Batch size is picked from your memory; data format is auto-detected.

  5. troy chat

    Talk to the adapter you just trained, streaming, in the same terminal.

  6. troy export -f gguf

    Fuse the adapter and ship it to llama.cpp, Ollama, or LM Studio — or -f ios and run it in your iPhone app.

The YAML file is the interface.

A training run is a config you can read, diff, and commit — not a notebook of glue code. Everything Troy needs fits on one screen, and everything it can infer, it infers.

  • Auto batch size — sized from this Mac’s unified memory.
  • Auto data format — Alpaca, ShareGPT, chat, completions, text, or preference pairs, detected from the first record.
  • Auto validation split — or point valid at your own file.

Unified memory changes what a laptop can train.

There is no VRAM wall on Apple Silicon — the GPU sees all of it. A 36 GB MacBook fine-tunes models that need a workstation GPU anywhere else. The examples below are sizing guidance, not a catalog: any architecture mlx-lm supports trains — thousands of ready conversions live on mlx-community.

DPO without the second model.

Preference tuning normally keeps a frozen reference copy of the model in memory — doubling the footprint exactly where unified memory is most precious.

Troy’s DPO trainer zeroes the LoRA scales to recover the reference model from the policy model itself. Same math, no second copy of the weights.
